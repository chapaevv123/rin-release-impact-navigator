# Current limitations

1. The default Starlette project snapshot and HTTPX release are real pinned public source. Its exact old-version requirements pin is a local reproduction environment, not Starlette's repository lockfile. The separate sponsor E2E application is synthetic.
2. AST analysis covers direct imports, aliases and typed-parameter attributes. Re-exports, wrappers, subclassing, configuration and indirect dependency use are not resolved. `getattr`, dynamic imports and `**kwargs` produce blind spots.
3. The Starlette case has a recorded local differential PASS→TypeError for TestClient construction. The bundle hashes the two output files but does not independently rerun their environments; the Flask sponsor fixture remains L2 static usage only.
4. Zetaris processed inline snapshot-derived values. A separate read-only query of an already registered public CSV source passed. Two RIN evidence CSVs are prepared, but no RIN source registration, live connector join or durable RIN source tables have been shown.
5. Meterless uses an in-memory reference engine for each run. A local real-case graph read/write receipt exists, but cross-run persistence is absent.
6. The recorded UI is replay. Refreshing it does not run sponsor services again.
7. Nemotron is not used in the current case. The owner reports Cursor Agent development use, independently supported by the resulting code and tests; original account screenshots and chat ID are not locally retained. Cursor is not a runtime component of the captured case.
8. Frozen 12-case benchmark inputs and labels were not changed, but RIN has not produced valid full-case results because the benchmark metadata lacks pinned project source snapshots needed by this engine.
9. `NO_ACTION` is intentionally unavailable until constraints, extras, transitive paths and dynamic usage can be verified within an explicit scope.
